## version 字段研判

手册内的产品版本证据（全量复核结果）：

| 证据 | 位置 | 内容 |
|---|---|---|
| TCP 多核/并发传输 | 10.30 TransportConfigQosPolicy 表，**p157**（第13章 p197-211 为其配置详解） | `TCP 多核传输 (>=2.4.0)  tcpv4_cc` —— **该功能要求 2.4.0 以上版本** |
| 实体 ID 指定 | 10.37.2，p164-165 | "自 ZRDDS 2.3.0 起，支持用户对 DDS 实体的实例句柄进行指定" |
| PropertyQosPolicy 特性扩展 | 10.37，p163 | "自 ZRDDS 2.2.7 起，部分新增特性将采用 PropertyQosPolicy 进行扩展" |
| 日志 API | 25.4.2，p281-285 | `ZRLogInitial() / ZRLogDestroy()（支持版本>=2.2.7）` |
| Docker 安装包 | 24.3，p276 | 安装包文件名 `ZRDDSSetupX64GCC4.8.4-2.2.7.tar.gz`（随书版本 2.2.7） |

研判：

1. 手册实体版本标 **2.0**（封面/元数据），但正文记载的功能版本约束已达 **2.2.7 ~ ≥2.4.0**——文档版本落后于产品，这本身就是手册的质量事实。
2. `version` 标注的依据在**功能粒度**：凡命中上述功能的题（如"如何启用 TCP 并发传输"→ 2.4.0+）有真值可标；其余题（安装/环境变量/简化接口等）手册未给版本描述，应标文档实体版本 2.0 或留空。
3. 早期标注把 `v2.3+` 一刀切打给 12 道题，是**未按功能核对**的粗标。
4. Q010（v2.4 vs v2.3 整体差异与升级建议）维持"不存在信息"研判：手册只有零散的功能级版本注记，无系统性版本对比章节。
5. v2.4 完整文档实体在 Doxygen HTML 源（`data/raw/developer-guides/cdoc_html/`）。

**标注建议**：正式问题集的 `version` 按**功能级版本约束**标注——命中上表功能者填手册真值（如 `2.4.0+`），无版本描述者填知识源实体版本 `2.0`；跨版本系统性差异题走多来源实验（HTML 源可提供 v2.4 侧证据）。

## 结论与用途

- **"不存在信息"题候选（4 道）**：Q001（connect）、Q003（E1003）、Q004（DomainParticipant.connect）、Q010（v2.3/v2.4 差异）——这 4 道天然满足拒答专项的出题需求，只需改 `type` 并清空 `expected_sources`。
- **页码真值口径**：一律以 Node 产物 `metadata.printed_page_start/end` 为准（上表"实际位置"列可直接引用），不凭阅读器翻页印象标注。
- **跨来源题**：Q015 属"HTML 更适合回答"组，随多来源知识库接入后出题。
